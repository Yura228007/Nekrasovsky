# Создание базы данных и применение миграций

## Проблема
Если при запуске сервера вы видите ошибки типа `relation "User" does not exist`, это означает, что база данных не создана или миграции не применены.

## Решение

### Вариант 1: Автоматическое применение миграций (рекомендуется)
Сервер автоматически применяет миграции при запуске. Просто запустите сервер:

```bash
cd server/server
dotnet run
```

Если миграции еще не созданы, перейдите к Варианту 2.

### Вариант 2: Создание миграций вручную

#### Шаг 1: Установите инструменты EF Core (если еще не установлены)

```bash
dotnet tool install --global dotnet-ef
```

Если уже установлено, обновите:
```bash
dotnet tool update --global dotnet-ef
```

#### Шаг 2: Убедитесь, что PostgreSQL запущен и база данных существует

```bash
# Проверьте подключение к PostgreSQL
psql -h localhost -U postgres
```

Если база данных `Nekrasovsky` не существует, создайте её:

```sql
CREATE DATABASE Nekrasovsky;
\q
```

#### Шаг 3: Создайте миграцию

```bash
cd server/server
dotnet ef migrations add InitialCreate
```

#### Шаг 4: Примените миграции к базе данных

```bash
dotnet ef database update
```

#### Шаг 5: Запустите сервер

```bash
dotnet run
```

## Проверка

После применения миграций вы должны увидеть в логах:
```
Database migrations applied successfully.
```

И все таблицы должны быть созданы в базе данных `Nekrasovsky`.

## Создание пользователя-администратора

После того как база данных создана, вы можете создать пользователя через API:

```bash
curl -X POST http://localhost:5000/api/users \
  -H "Content-Type: application/json" \
  -d '{
    "login": "admin",
    "encryptedPassword": "admin123",
    "name": "Администратор",
    "surname": "Системы",
    "email": "admin@nekrasovsky.local"
  }'
```

Затем создайте разрешение Admin и назначьте его пользователю (см. инструкции в основном README).

## Дополнительные команды

### Просмотр списка миграций
```bash
dotnet ef migrations list
```

### Откат последней миграции
```bash
dotnet ef database update PreviousMigrationName
```

### Удаление последней миграции (если еще не применена)
```bash
dotnet ef migrations remove
```

### Создание новой миграции после изменения моделей
```bash
dotnet ef migrations add MigrationName
dotnet ef database update
```
