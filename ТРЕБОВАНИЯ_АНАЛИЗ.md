# Анализ соответствия проекта функциональным и нефункциональным требованиям

## Функциональные требования

### ✅ 1. Авторизация пользователей
- **✅ Вход в систему по логину и паролю**: Реализовано в `AuthService.cs`, есть метод `LoginAsync`
- **✅ Регистрация новых сотрудников (только администраторам)**: Реализовано в `UsersController.cs` с атрибутом `[RequirePermission("ManageUsers")]`

### ⚠️ 2. Управление запросами на продукт
- **✅ Сотрудники могут создавать запросы**: Реализовано через `PartRequest` модель и `PartRequestsController`
- **⚠️ Информация в запросах**:
  - ✅ Имя сотрудника: есть `FromUser` (навигационное свойство)
  - ⚠️ Название продукта: есть только `Material`, но нет прямого поля "название продукта"
  - ✅ Количество: есть `Quantity`
  - ✅ Дата и время создания: есть `CreatedAt`
  - ✅ Статус запроса: есть `Status` (Pending, Approved, Rejected)
- **✅ Администраторы могут просматривать и изменять статус**: Реализовано через методы `Approve` и `Reject` в `PartRequestsController`

### ✅ 3. Формирование отчетов
- **✅ Ежедневный отчет для каждого сотрудника**: Реализовано через `WorkReport` с полем `Date`
- **✅ Количество отработанных часов**: Можно вычислить из `StartWork` и `FinishWork`
- **✅ Список отправленных запросов за день**: **РЕАЛИЗОВАНО** - добавлен метод `GetPartRequestsForWorkReportAsync` в `WorkReportService` и endpoint `GET /api/work-reports/{id}/part-requests`
- **✅ Примечания**: Есть поле `Note` в `WorkReport`
- **✅ Отчеты сохраняются в БД**: Реализовано через `WorkReportService`

### ✅ 4. Администрирование
- **✅ Просматривать список всех сотрудников**: Реализовано в `UsersController.GetAll()`
- **✅ Остановка работы цеха**: **РЕАЛИЗОВАНО** - добавлено поле `IsActive` в модель `Warehouse`, методы `StopWarehouseAsync` и `StartWarehouseAsync` в `WarehouseService`, API endpoints `/api/warehouses/{id}/stop` и `/api/warehouses/{id}/start` с проверкой прав `[RequirePermission("ManageWarehouses")]`
- **✅ Управление учетными записями**: Реализовано (Create, Update, Delete) с проверкой прав `[RequirePermission("ManageUsers")]`
- **✅ Просматривать все запросы и отчеты**: Реализовано через соответствующие контроллеры

### ✅ 5. Передача товара между цехами
- **✅ Принять товар**: Реализовано через `ApprovePartRequestAsync`
- **✅ Отказаться от товара**: Реализовано через `RejectPartRequestAsync`
- **✅ Уведомление при 3 отказах**: **РЕАЛИЗОВАНО** - реализован счетчик отказов в `PartRequestService`, SignalR Hub `NotificationHub` для отправки уведомлений администраторам/супервайзерам при достижении 3 отказов

### ✅ 6. Передача смены
- **✅ Проверка остатков перед передачей**: **РЕАЛИЗОВАНО** - добавлена проверка `FillingWarehouse` перед созданием `ShiftTransfer` в `ShiftTransferService.CreateShiftTransferAsync`
- **✅ Подтверждение передачи смены**: Реализовано через `IsConfirmed` и метод `ConfirmShiftTransferAsync`

### ⚠️ 7. Кнопка Alarm
- **✅ Использование при пожаре/ЧП/поломке**: Реализовано через `AlarmEvent` модель
- **❌ Уведомления всем пользователям с звуковым сигналом**: **НЕ РЕАЛИЗОВАНО** - нет SignalR/WebSocket для real-time уведомлений
- **✅ Информация о событии**: Есть поля `Message`, `Location`, `User` (кто нажал), `CreatedAt`

### ✅ 8. Считывание данных о продукте
- **✅ Распознавание штрих-/QR-кодов**: **РЕАЛИЗОВАНО** - интегрирован `ZXing.Net.Maui.Controls` версии 0.5.1, добавлены разрешения камеры для Android и iOS

## Нефункциональные требования

### ⚠️ Производительность
- **⚠️ Стабильность при большом количестве данных**: Архитектура позволяет, но не было нагрузочного тестирования
- **❌ Время загрузки окна не должно превышать 2 секунды**: **НЕ ПРОВЕРЕНО** - нет метрик производительности

### ⚠️ Безопасность
- **✅ Пароли в зашифрованном виде (хэширование)**: **РЕАЛИЗОВАНО** - заменено AES шифрование на BCrypt хэширование (`BCrypt.Net-Next` версии 4.0.3)
- **✅ SSL/TLS подключение**: Реализовано в `Program.cs` с поддержкой HTTPS и кастомных сертификатов
- **✅ Защита от SQL-инъекций**: Используется Entity Framework Core (ORM) с параметризованными запросами. В `Program.cs` используется `ExecuteSql` вместо `ExecuteSqlRaw` для предотвращения SQL-инъекций
- **❌ На телефонах автоматически открывается приложение**: **НЕ РЕАЛИЗОВАНО** - нет deep linking или автоматического запуска

### ✅ Масштабируемость
- **✅ Поддержка увеличения числа пользователей**: Архитектура позволяет масштабирование
- **✅ База данных оптимизирована**: Используется PostgreSQL с индексами через Entity Framework Core

### ✅ Пользовательский интерфейс
- **✅ Интуитивно понятный интерфейс**: Реализован темный UI/UX дизайн
- **✅ Адаптивный дизайн**: MAUI поддерживает Windows и Android
