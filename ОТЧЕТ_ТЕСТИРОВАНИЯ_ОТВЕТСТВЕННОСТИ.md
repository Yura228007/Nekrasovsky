## 🧪 Что нужно протестировать вручную

### 1. Назначение ответственности с количеством

**Тест 1.1: Назначение без количества (обратная совместимость)**
```
POST /api/responsibilities/material/{materialId}/assign
Body: { "userId": 1 }
```
- Ожидается: Ответственность создается с `Quantity = null` (ответственность за весь материал)

**Тест 1.2: Назначение с количеством**
```
POST /api/responsibilities/material/{materialId}/assign
Body: { "userId": 1, "quantity": 100, "measuringUnit": "кг" }
```
- Ожидается: Ответственность создается с указанным количеством

**Тест 1.3: Несколько пользователей на один материал**
```
POST /api/responsibilities/material/1/assign
Body: { "userId": 1, "quantity": 50 }
POST /api/responsibilities/material/1/assign
Body: { "userId": 2, "quantity": 30 }
```
- Ожидается: Оба пользователя имеют активную ответственность за материал 1 с разными количествами

### 2. Автоматическое уменьшение количества

**Тест 2.1: Переработка материалов**
1. Назначить ответственность: пользователь 1 за материал 1, количество 100
2. Выполнить переработку материала 1, количество 30
3. Проверить: ответственность пользователя 1 должна иметь `Quantity = 70`

**Тест 2.2: Уменьшение до нуля**
1. Назначить ответственность: пользователь 1 за материал 1, количество 50
2. Выполнить переработку материала 1, количество 50
3. Проверить: 
   - `Quantity = 0`
   - `IsActive = false`
   - `ReleasedAt` установлен

**Тест 2.3: Несколько пользователей при использовании**
1. Назначить:
   - Пользователь 1: материал 1, количество 100
   - Пользователь 2: материал 1, количество 50
2. Выполнить переработку материала 1, количество 120
3. Проверить:
   - Пользователь 1: `Quantity = 0`, `IsActive = false` (использовано 100)
   - Пользователь 2: `Quantity = 0`, `IsActive = false` (использовано 20 из 50)

### 3. Получение ответственности

- Ожидается: Возвращаются все активные назначения материалов (нужно обновить для отображения количества)

### 4. Проверка ответственности

**Тест 4.1: IsResponsibleForMaterialAsync**
- Проверить, что метод корректно работает с новой системой количества
- Пользователь должен считаться ответственным, если у него есть активная ответственность (независимо от количества)

## 📝 Замечания

1. **Метод `IsResponsibleForMaterialAsync`** - сейчас проверяет только наличие активной ответственности, не учитывает количество. Это может быть правильным поведением (если пользователь ответственный, то он ответственный за все, что у него есть).

2. **Метод `ReleaseMaterialAsync`** - освобождает только одну ответственность (первую найденную). При наличии нескольких пользователей это может быть проблемой. Возможно, нужно добавить параметр `userId`.

3. **Методы `GetActiveMaterialAssignmentsAsync`** - нужно обновить для возврата информации о количестве.

4. **Интеграция в других местах** - нужно добавить автоматическое уменьшение количества в:
   - PartRequests (при одобрении запроса)
   - ProductOutput (если используется материал)
   - Другие операции использования материалов
