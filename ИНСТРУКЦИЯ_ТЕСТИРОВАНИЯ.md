# Инструкция по тестированию системы ответственности с количеством

## Быстрый старт

### 1. Запуск сервера

```powershell
cd Nekrasovsky\server\server
dotnet run
```

Сервер запустится на:
- HTTP: `http://localhost:9000`
- Swagger UI: `http://localhost:9000/swagger`

### 2. Тестирование через Swagger (рекомендуется)

1. Откройте браузер: `http://localhost:9000/swagger`
2. Найдите раздел `Responsibilities`
3. Протестируйте следующие endpoints:

#### Тест 1: Назначение без количества
```
POST /api/responsibilities/material/{materialId}/assign
Body:
{
  "userId": 1
}
```
**Ожидаемый результат:** Ответственность создана с `quantity: null`

#### Тест 2: Назначение с количеством
```
POST /api/responsibilities/material/{materialId}/assign
Body:
{
  "userId": 1,
  "quantity": 100,
  "measuringUnit": "кг"
}
```
**Ожидаемый результат:** Ответственность создана с указанным количеством

#### Тест 3: Несколько пользователей
```
POST /api/responsibilities/material/1/assign
Body: { "userId": 1, "quantity": 50 }

POST /api/responsibilities/material/1/assign
Body: { "userId": 2, "quantity": 30 }
```
**Ожидаемый результат:** Оба пользователя имеют активную ответственность

#### Тест 4: Получение ответственностей
```
GET /api/responsibilities/user/1
```
**Ожидаемый результат:** Список всех ответственностей пользователя с полями `quantity` и `measuringUnit`

### 3. Тестирование автоматического уменьшения

1. Назначьте ответственность с количеством:
   ```
   POST /api/responsibilities/material/1/assign
   Body: { "userId": 1, "quantity": 100 }
   ```

2. Выполните переработку материала:
   ```
   POST /api/reprocessings
   Body: {
     "warehouseId": 1,
     "sources": [{"materialId": 1, "quantity": 30, "measuringType": "кг"}],
     "outputs": [...]
   }
   ```

3. Проверьте уменьшение количества:
   ```
   GET /api/responsibilities/user/1
   ```
   **Ожидаемый результат:** `quantity` должен быть 70

4. Используйте весь материал (quantity = 100):
   ```
   POST /api/reprocessings
   Body: {
     "warehouseId": 1,
     "sources": [{"materialId": 1, "quantity": 70, "measuringType": "кг"}],
     "outputs": [...]
   }
   ```
   **Ожидаемый результат:** 
   - `quantity = 0`
   - `isActive = false`
   - `releasedAt` установлен

### 4. Тестирование через PowerShell скрипт

```powershell
cd Nekrasovsky\server
.\test_responsibility.ps1
```

**Важно:** Перед запуском скрипта:
1. Убедитесь, что сервер запущен
2. Отредактируйте скрипт: замените `$materialId` и `$userId` на реальные ID из вашей БД
3. Убедитесь, что пользователь с ID в `X-User-Id` имеет права администратора

## Проверка результатов

### В базе данных

Выполните SQL запрос:
```sql
SELECT 
    r."Id",
    r."UserId",
    u."Name" || ' ' || u."Surname" as "UserName",
    r."MaterialId",
    m."Name" as "MaterialName",
    r."Quantity",
    r."MeasuringUnit",
    r."IsActive",
    r."AssignedAt",
    r."ReleasedAt"
FROM "Responsibility" r
LEFT JOIN "User" u ON r."UserId" = u."Id"
LEFT JOIN "Material" m ON r."MaterialId" = m."Id"
WHERE r."IsActive" = true
ORDER BY r."AssignedAt" DESC;
```

### Через API

```
GET /api/responsibilities/user/{userId}
GET /api/responsibilities/materials/active
GET /api/responsibilities/material/{materialId}
```

## Возможные проблемы

1. **Ошибка 403 Forbidden**
   - Убедитесь, что пользователь в заголовке `X-User-Id` имеет права администратора
   - Проверьте, что пользователь существует в БД

2. **Ошибка 404 Not Found**
   - Проверьте, что материал/продукт с указанным ID существует
   - Проверьте правильность URL

3. **Количество не уменьшается**
   - Убедитесь, что переработка выполняется успешно
   - Проверьте логи сервера на наличие ошибок
   - Убедитесь, что материал действительно используется в переработке

## Что проверить

- [ ] Назначение ответственности без количества работает
- [ ] Назначение ответственности с количеством работает
- [ ] Несколько пользователей могут быть ответственными за один материал
- [ ] Количество автоматически уменьшается при переработке
- [ ] Ответственность автоматически освобождается при quantity = 0
- [ ] API возвращает поля quantity и measuringUnit
- [ ] Обратная совместимость сохранена (старые записи с quantity = null работают)
