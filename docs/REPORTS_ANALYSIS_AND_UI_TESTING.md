## 2. Сопоставление с текущей реализацией

### 2.1. Отчёт о смене (Shift Report) vs report1

**Что совпадает:**

- Дата смены и тип (день/ночь) — есть в шапке отчёта.
- ФИО сотрудника — в шапке («Фамилия» + имя).
- Линия — выводится как «Станок» (Machine) по строкам производства.
- Артикул — выводится (Product.Code).
- Выпущено — ProducedQuantity.
- Брак — DefectQuantity.
- Эко — EcoQuantity (в образце report1 «брак на переработку» и «особые отметки»; у нас эко — отдельная колонка).

**Что не совпадает или отсутствует:**

| В образце report1 | В текущем коде |
|-------------------|----------------|
| **Цвет** | Нет в модели Product и ProductOutput — не сохраняется и не выводится. |
| **Краситель** | Нет в модели — не сохраняется и не выводится. |
| **Брак на переработку** (отдельно от «прочего» брака) | Есть только общий «Брак» (DefectQuantity). Разбиения «на переработку» / «невозвратный» в отчёте нет. |
| **Особые отметки по строке** | В БД есть ProductOutput.Note, но в Excel-отчёте о смене это поле не выводится. В отчёт попадают только общие «Особые отметки» из WorkReport.Note. |

**Вывод:** Текущий отчёт о смене частично соответствует report1 (дата, ФИО, линия, артикул, выпущено, брак, эко). Не хватает: цвет, краситель, разделения брака «на переработку», вывода примечаний по каждой строке производства.

---

### 2.2. Отправки (перемот / упаковка / Эко) vs report2

**В образце report2:** по артикулу и дате/смене фиксируются три направления: «на перемот», «на упаковку», «в Эко».

**В текущем коде:**

- В выпуске (ProductOutput) есть только: ProducedQuantity, DefectQuantity, EcoQuantity.
- «Отправлено в Эко» можно отображать из EcoQuantity.
- Отдельных полей или отчётов «отправлено на перемот» и «отправлено на упаковку» нет — такие движения не хранятся и в отчётах не выводятся.

**Вывод:** report2 в текущей реализации не реализован. Нет ни хранения, ни отчёта по «перемот» и «упаковка»; только «Эко» частично покрывается полем EcoQuantity в отчёте о смене.

---

### 2.3. Ведомость по складам vs report3

**В образце report3:** по артикулу/номенклатуре — начальный остаток, приход, расход (в т.ч. WB), отгрузка коробок, конечный остаток.

**В текущем коде:**

- Есть остатки по складам (FillingWarehouse: материал/продукт, склад, количество).
- Нет «начальный остаток на дату», «приход за период», «расход за период», «конечный остаток» в формате report3.
- Нет отдельного учёта «расход WB» или «отгружено коробок» как в образце.

**Вывод:** report3 в виде ведомости по товарам на складах с оборотами (приход/расход/остатки) в текущей системе не реализован. Есть только текущие остатки (FillingWarehouse), без отчёта в формате report3.

## 3. Проверка: всё ли сохраняется корректно в текущем коде

### 3.1. WorkReport (смена)

- Сохраняется: UserId, Date, StartWork, FinishWork, Note.  
- При завершении смены вызывается генерация Shift Report; при ошибке генерации смена всё равно сохраняется, но файл отчёта может не создаться.

**Корректность:** данные смены сохраняются. Связь «смена → отчёт» зависит от успешности `GenerateReportAsync` после FinishWork.

### 3.2. ProductOutput (выпуск)

- Сохраняется: UserId, WorkReportId (опционально), ProductId, WarehouseId, MachineId, ProducedQuantity, DefectQuantity, EcoQuantity, MeasuringUnit, Note, CreatedAt.  
- В отчёт о смене попадают строки по условию: UserId = пользователь смены и CreatedAt в интервале [StartWork, FinishWork]. WorkReportId при отборе не используется.

**Корректность:** сохранение полей корректно. В Excel не выводятся: WarehouseId, Note по строке. Если выпуски вводятся без привязки к смене по времени, они могут не попасть в отчёт (важно, чтобы время создания было внутри смены).

### 3.3. PartRequest (заявки на перемещение)

- В отчёт смены попадают заявки: FromUserId = пользователь смены, CreatedAt в интервале смены.  
- Сохраняются все нужные поля (материал, количество, склады, статус и т.д.) и в листе «Заявки на перемещение» выводятся корректно.

**Корректность:** сохранение и вывод в отчёт согласованы.

### 3.4. Responsibility (ответственности)

- В отчёт смены попадают активные ответственности пользователя (UserId, IsActive).  
- Используется таблица Responsibility (без разбивки по складам). ResponsibilityFilling в отчёт не попадает.

**Корректность:** то, что хранится в Responsibility, в отчёте отображается. Если часть ответственности учитывается только в ResponsibilityFilling, в текущем отчёте этого не будет.

### 3.5. Shift Report (файл отчёта)

- Генерируется при завершении смены; файл пишется в `reports/`, запись — в таблицу ShiftReport (FileName, FilePath, FileSize, WorkReportId, UserId, ShiftStart, ShiftEnd, Summary).  
- При скачивании файл читается с диска по FilePath.

**Корректность:** при отсутствии ошибок при записи файла и пути сохранение и выдача файла корректны. Если генерация упала после FinishWork, у смены не будет записи ShiftReport и скачивание будет недоступно.

## 4. Инструкция по тестированию отчётов через UI (шаг за шагом)

Ниже — сценарий проверки текущего поведения: смена, выпуск, завершение смены, генерация и скачивание отчёта о смене.

### Предусловия

- Сервер запущен, приложение (MAUI) подключено к нему.
- Есть пользователь с правом работать со сменами (доступ к «Рабочие отчёты»).
- В системе есть: минимум один продукт (с артикулом/кодом), при необходимости — склад, станок/линия; при необходимости — заявки на перемещение и ответственности для проверки дополнительных листов.

---

### Шаг 1. Вход в приложение

1. Откройте приложение.
2. Введите логин и пароль пользователя.
3. Убедитесь, что открылась главная страница (например, с карточками разделов).

**Ожидаемый результат:** авторизация прошла, отображается главный экран.

---

### Шаг 2. Переход к рабочим отчётам

1. На главной найдите карточку, связанную с рабочими отчётами / сменами (например, «Рабочие отчёты» или «Отчёты»).
2. Нажмите на неё.

**Ожидаемый результат:** открывается страница «Рабочие отчёты» (список смен, кнопки «Начать работу», «Обновить»).

---

### Шаг 3. Начать смену

1. На странице «Рабочие отчёты» нажмите «Начать работу» (в тулбаре или на экране).
2. Дождитесь завершения запроса (без сообщения об ошибке).

**Ожидаемый результат:** в списке появляется новая смена с текущей датой, временем начала и кнопкой «Завершить работу»; кнопка «Начать работу» может скрыться или стать недоступной, если разрешена только одна активная смена.

---

### Шаг 4. Записать выпуск продукции (для проверки листа «Производство» в отчёте)

1. Перейдите на раздел выпуска продукции (например, «Выпуск» с главной).
2. Нажмите добавление новой записи выпуска.
3. Выберите продукт (желательно с заполненным артикулом/кодом).
4. Выберите склад (если требуется).
5. При необходимости выберите станок/линию.
6. Введите количество произведённой продукции (например, 10).
7. Введите количество брака (например, 0 или 1).
8. Введите количество эко (например, 0 или 1).
9. Сохраните запись.

**Ожидаемый результат:** запись выпуска сохраняется; при наличии ограничений по ответственности — сохранение возможно только в рамках доступного лимита.

---

### Шаг 5. (По желанию) Создать заявку на перемещение

1. Перейдите в раздел заявок на детали/перемещение.
2. Создайте заявку (материал, количество, склады и т.д.) и сохраните.

**Ожидаемый результат:** заявка создана и отображается в списке. Она попадёт в отчёт смены, если время создания попадает в интервал смены и вы — отправитель.

---

### Шаг 6. Завершить смену

1. Вернитесь на страницу «Рабочие отчёты».
2. Найдите только что начатую смену (текущая дата, есть «Завершить работу»).
3. Нажмите «Завершить работу».
4. Дождитесь ответа сервера (успех или сообщение об ошибке).

**Ожидаемый результат:** у смены появляется время окончания; кнопка «Завершить работу» заменяется на «Скачать отчёт» (или аналог). Сообщение об успешном завершении смены.

---

### Шаг 7. Скачать отчёт о смене

1. На той же карточке смены нажмите «Скачать отчёт» (или «Скачать отчёт смены»).
2. Дождитесь загрузки файла (могут показаться индикатор или сообщение об успехе).

**Ожидаемый результат:** файл xlsx сохраняется в папку загрузок (Android) или «Мои документы» (Windows); приложение показывает сообщение об успешном сохранении и имя файла. При отсутствии прав или отсутствии сгенерированного отчёта — сообщение об ошибке.

---

### Шаг 8. Проверить содержимое скачанного xlsx

1. Откройте скачанный файл в Excel (или аналоге).
2. Проверьте лист «Отчёт о смене»:
   - В шапке: дата смены, тип (день/ночь), ФИО, должность, время начала и окончания, продолжительность, особые отметки (если вы их вводили в смену).
   - Блок «ПРОИЗВОДСТВО»: колонки Артикул, Продукт, Станок, Выпущено, Брак, Эко, Ед.изм. — должны совпадать с введёнными данными выпуска (шаг 4).
   - Итоговая строка по выпуску/браку/эко.
   - Внизу — подписи работника и старшего, дата формирования отчёта.
3. Если вы создавали заявки (шаг 5) и они попали в смену по времени и отправителю — откройте лист «Заявки на перемещение» и убедитесь, что там есть нужные строки.
4. Если у пользователя есть активные ответственности (Responsibility) — откройте лист «Ответственности» и проверьте, что они отображаются.

**Ожидаемый результат:** данные в файле соответствуют введённым: смена, выпуск (артикул, продукт, станок, выпущено/брак/эко), при наличии — заявки и ответственности.

---

### Шаг 9. Проверка ошибок и граничных случаев

**9.1. Скачивание без завершённой смены**

- Не завершайте смену и попробуйте скачать отчёт (если в UI такая кнопка доступна только после завершения — шаг пропустить).  
- **Ожидаемый результат:** отчёт недоступен или показывается сообщение, что отчёт не найден/ещё не сформирован.

**9.2. Другая смена, другой пользователь (если есть права)**

- Под учётом с правами администратора/владельца откройте список смен другого пользователя (если такой экран есть) и попробуйте скачать его отчёт.  
- **Ожидаемый результат:** при наличии прав — файл скачивается; без прав — отказ (403 или сообщение об ошибке).

**9.3. Смена без выпуска**

- Завершите смену, в которой не было ни одной записи выпуска.  
- **Ожидаемый результат:** отчёт создаётся; на листе «Отчёт о смене» в блоке производства — текст вроде «Нет данных о производстве» или пустая таблица, шапка смены заполнена.

### Краткий чек-лист по шагам

| Шаг | Действие | Что проверить |
|-----|----------|-------------------------------|
| 1 | Вход | Успешная авторизация |

## 5. Итог

- **report1:** частично совпадает с текущим отчётом о смене (дата, ФИО, линия, артикул, выпущено, брак, эко). Не совпадают: цвет, краситель, отдельное «брак на переработку», вывод примечаний по строке (ProductOutput.Note).
- **report2:** в системе не реализован (нет «перемот»/«упаковка»; «Эко» частично есть в колонке Eco в отчёте о смене).
- **report3:** ведомость по складам в формате образца не реализована (нет отчёта с оборотами и остатками в виде report3).
- Сохранение данных по смене, выпуску, заявкам и ответственностям в текущем коде выполняется корректно; в отчёт о смене не выводятся ProductOutput.Note и WarehouseId.
- Инструкция выше позволяет пошагово проверить в UI: создание смены, ввод выпуска, завершение смены, генерацию и скачивание отчёта, а также содержимое xlsx и граничные случаи.

Если нужно, можно отдельно расписать тест-кейсы под доработку отчётов до формата report1/report2/report3 (новые поля, новые отчёты).
